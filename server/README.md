# 챗봇 관리 서버

## 로컬 실행

`github_upload` 폴더에서 실행합니다.

```powershell
python server/server.py
```

서버가 실행되는 동안 [관리자](http://127.0.0.1:8000/admin), [대시보드](http://127.0.0.1:8000/sns.html), [문의 페이지](http://127.0.0.1:8000/inquiry.html)를 이용할 수 있습니다. 처음 생성되는 계정은 `admin` / `1234`입니다. 계정 설정에서 비밀번호를 변경하면 모든 로그인 세션이 종료됩니다.

공개 페이지의 **챗봇 스튜디오** 링크는 상대 주소 `chatbot-studio.html`로 연결됩니다. 관리 서버에서 제공되는 사이트는 공개 상태 확인 API를 통해 같은 서버의 로그인 화면으로 이동합니다. `127.0.0.1` 등의 로컬 정적 미리보기에서는 `http://127.0.0.1:8000`의 관리 서버도 확인합니다. 관리 서버가 없는 GitHub Pages에서는 404 대신 연결 안내를 표시합니다. 공개 사이트에서 로그인·게시 기능을 운영하려면 아래 외부 배포 안내에 따라 서버를 별도로 배포해야 합니다.

로그인 화면에는 체험 계정 `admin` / `1234`가 표시되고 미리 입력됩니다. 로그인 버튼을 누르면 서버 인증 후 관리자 화면으로 이동합니다. 실제 비밀번호를 변경한 경우 로그인 화면의 체험 안내와 기본 입력값도 함께 수정합니다.

다른 포트는 `python server/server.py --port 8001`로 지정합니다. 기본 바인딩은 현재 컴퓨터만 접근 가능한 `127.0.0.1`입니다.

## 편집과 게시

1. **안내 콘텐츠**에서 챗봇 제목, 기본 답변, 단계별 답변·키워드·버튼·다음 단계를 편집합니다. 새 단계의 ID는 소문자 영문으로 시작하는 영문·숫자·하이픈·밑줄이며, 시작 단계는 `home`입니다. 다른 버튼에 연결된 단계는 연결을 해제한 후 삭제할 수 있습니다.
   관련 페이지 링크는 사이트 내부 HTML 경로로 설정합니다. ‘페이지별 안내 연결’은 각 공개 화면의 ‘현재 페이지 안내’가 이동할 단계를 지정합니다. 해당 연결에서 사용 중인 단계도 연결 해제 후 삭제할 수 있습니다.
2. **초안 저장**은 비공개 저장입니다. **미리보기**도 현재 내용을 초안으로 저장하고, 실제 공개 챗봇과 동일한 렌더링·분기 코드를 사용한 미리보기를 생성합니다. 미리보기에서는 문의가 접수되지 않습니다.
3. 최신 미리보기가 로드되면 게시 메모를 입력하고 **최종 게시**합니다. 공개 JSON과 웹 챗봇에 그때 반영됩니다. 미리보기 이후 편집했거나 다른 창에서 초안·게시 버전을 변경했다면 다시 미리봐야 합니다. 미리보기는 생성한 로그인 세션에서 1시간 유효합니다.
4. **게시 버전**에서 변경 메모·시각·JSON 내용을 확인하고 JSON을 다운로드할 수 있습니다. **초안으로 불러오기**는 편집기에만 반영합니다. 다시 미리보고 게시하면 원래 버전을 보존한 채 새 버전 번호로 복원됩니다.

초안은 모든 관리자 창에서 공유됩니다. 수정 충돌 시 서버가 409 오류로 차단합니다. 필요한 미저장 내용을 따로 복사한 뒤 ‘서버 초안 다시 불러오기’로 최신 데이터를 읽습니다. 브라우저 화면의 시각은 한국 표준시(KST), DB의 시각은 UTC로 저장합니다.

## 문의함

공개 챗봇의 관리자 문의와 `inquiry.html`은 `/api/inquiries`를 통해 같은 `inquiries` 테이블에 저장됩니다. 이름·이메일·문의 내용·동의 일시가 보관됩니다. 공개 방문자는 문의 목록을 조회할 수 없으며 관리자만 새 문의 / 확인 / 처리 완료 상태로 관리할 수 있습니다. 이메일 자동 발송 기능은 없습니다.

관리자 편집 화면에서 실제 개인정보 수집 주체·목적·보관 기간을 설정하고 게시합니다. 기본 보관 기간은 접수일부터 30일입니다. 각 문의의 삭제 예정 시점은 **접수 당시 공개된 보관 기간**으로 확정됩니다. 운영 중 기간을 수정해도 기존 문의의 삭제 시점은 바뀌지 않습니다. 서버의 관리·안내 API 요청 시 보관 기한이 지난 문의를 정리하므로 만료된 내용은 문의함에 표시되지 않습니다. 서버가 중단되어 있는 동안에는 정리가 실행되지 않습니다.

문의함은 최근 500건까지 표시합니다. 상단 전체 건수와 표시 건수를 구분하며, 필터는 불러온 최근 500건에 적용됩니다. 기존에는 문의 저장 기능이 없었으므로 과거 문의 데이터는 없습니다.

## 데이터와 계정 보관

기존 SNS 전용 운영 DB를 사이트 전체 안내로 확장할 때는 `python server/upgrade_site_guides.py`를 한 번 실행합니다. 이전 DB를 `server/var/backup-before-site-guides.sqlite3`에 백업한 뒤, 기존 사용자 수정 답변·문의·미게시 초안을 보존하며 새 안내를 게시 버전으로 추가합니다. 미게시 초안은 공개 버전에 섞지 않습니다. 이미 확장한 DB에는 중복 적용하지 않습니다. 새로운 빈 DB는 전체 안내가 포함된 시드로 초기화됩니다.

- 기본 DB: `server/var/chatbot.sqlite3`. 비밀번호는 PBKDF2 해시, 세션 토큰은 해시로 보관합니다. 세션은 8시간이며 HttpOnly·SameSite 쿠키와 CSRF 토큰을 사용합니다.
- `users`, `sessions`, `versions`, `draft`, `previews`, `inquiries`, `rate_limits` 테이블을 사용합니다. 공개 정적 파일 경로로 DB·서버 소스·관리자 HTML에 접근하는 요청은 차단됩니다.
- `CHATBOT_DB` 환경 변수로 DB 경로를 바꿀 수 있습니다. **영구 볼륨**에 저장하고 SQLite의 온라인 backup API로 주기적으로 백업합니다. DB 실행 중 원본 파일 하나만 복사하면 WAL의 최신 기록이 빠질 수 있습니다.
- `ADMIN_PASSWORD`는 빈 DB의 최초 계정 생성 때만 적용됩니다. 이미 생성된 계정은 관리자 계정 설정에서 변경합니다. 환경 변수 변경으로 기존 비밀번호를 덮어쓰지 않습니다.
- `data/chatbot.json`은 최초 시드입니다. 이후 관리자 게시 데이터는 DB에서 읽습니다. JSON 파일을 수정하는 것만으로 기존 운영 DB의 게시 내용이 바뀌지 않습니다.
- `server/var/`는 Git에서 제외합니다. 문의 내용이나 운영 DB를 소스 저장소에 올리지 않습니다.

## 외부 배포

로컬 구현은 완료했으며 외부 호스팅 배포는 별도입니다. **GitHub Pages 등 정적 파일 호스팅만으로는 관리자 로그인·게시·문의 저장을 운영할 수 없습니다.** 공개 웹과 관리 페이지를 이 WSGI 서버의 같은 도메인에서 제공해야 합니다. 파일을 직접 여는 방식도 지원하지 않습니다.

실제 배포는 Python WSGI를 실행할 수 있는 서버와 영구 저장소가 필요합니다. 개발용 내장 서버 대신 Waitress를 사용할 수 있습니다.

```powershell
python -m pip install -r server/requirements.txt
waitress-serve --listen=127.0.0.1:8000 server.server:application
```

HTTPS 리버스 프록시 뒤에 두고 사이트 전체 요청을 이 서버로 전달합니다. 프록시가 `X-Forwarded-Proto: https`를 정확히 설정하며 백엔드 직접 접근을 차단하는 환경에서만 `TRUST_PROXY=1`을 설정합니다. 이 경우 로그인 쿠키에 Secure 속성이 추가됩니다. 운영 시작 전 최초 비밀번호와 개인정보 수집 주체를 실제 값으로 변경합니다.

## 검증

```powershell
python -m unittest discover -s server -p test_server.py -v
```

독립된 임시 DB로 인증·권한 차단·CSRF·초안 격리·게시·버전 복원·충돌 감지·재시작 보존·개인정보 동의·문의 만료·비밀번호 변경을 검증합니다. 운영 DB에는 테스트 내용을 넣지 않습니다.
